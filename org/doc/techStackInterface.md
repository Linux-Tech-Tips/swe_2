# Tech Stack Interfacing Notes

This document briefly describes the interfacing between the various components of the tech stack.

## Components

The main components are the Backend, Frontend and the Database.
Within the Backend, the Scheduler exists as a separate subcomponent to the the user system.

## Communication between the components

**Backend <-> Frontend**

- Timetable availability information
  - array of 40 integer values with values of either 0 or 1
  - flattened 2D array of timeslots within days, joining the rows
- User registration information
  - user details, type, name, email, student/staff ID as per the User class
- Authentication information
  - whatever OAuth2 needs once that component's done
- Scheduler constraints information
  - scheduler constraints details, student limit, minimum required TAs and additional blocked times as per the Constraints class
- Scheduler optimal times information
  - optimal times generated by the scheduler, indices in the array of 40 timeslots

**Backend Internal Communication**

- Student repository:
  - getting saved student data, including timetable information
  - used by the scheduler to access student timetable details
- Module repository:
  - getting saved module data, including users
  - used by the scheduler to access student lists for a module
- Lecturer repository:
  - getting saved lecturer data

**Backend <-> Database**

- Students, Lecturers and Modules will be stored in a database using the repository system
- The database repositories will be implementations of the repository interfaces
