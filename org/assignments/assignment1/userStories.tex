\section{Provisional User Stories}
These are the provisional user stories for the project which may be subject to slight change as the project progresses.

\begin{enumerate}
\item As a user, I want the web app to be user friendly so that the information could be readable from a screen reader.\\
	\textbf{Acceptance Criteria:} When a screen reader plugin is enabled, it accurately works with the web-app.\\
        \textbf{Priority:} Low 

\item As a student, I want to be able to enter the time I'm busy so that the lecturer is aware of my unavailability.\\
		\textbf{Acceptance Criteria: }When the time slots are submitted, they appear on the student's timetable and are excluded from the times provided to the lecturers.\\
		\textbf{Priority:} High 

\item As a lecturer, I want to be able to limit the number of students in a tutorial slot so that certain venues are accessible.\\
		\textbf{Acceptance Criteria:} When a student limit is submitted to the web app, the generated timetable will contain more tutorials to accommodate the number of students.\\
		\textbf{Priority:} Low

\item As a lecturer, I want to be able to limit the number of tutorials a week so that the TAs don't get over worked.\\
		\textbf{Acceptance Criteria:} When the tutorial limit is submitted, the timetable ideally has no more than the specified limit of tutorials.\\
		\textbf{Priority:} Medium

\item As a lecturer, I want to be able to enter a list of student IDs so that I receive a list of times in which the students are available.\\
		\textbf{Acceptance Criteria:} When a list of enrolled student ids are submitted, a timetable is generated to display the available times.\\
		\textbf{Priority:} High

\item As a lecturer, I want to be able to block out a time slot so that it isn't considered for the scheduling algorithm.\\
		\textbf{Acceptance Criteria:} When the timeslot is blocked out, it is visually noted on the timetable and can't be a tutorial slot.\\
		\textbf{Priority:} Medium
\end{enumerate}
